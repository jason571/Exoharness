# 文件交付与预览

图片、视频、音频、文档和项目文件通过同一 Artifacts 服务交付。输入附件、执行中间文件与最终产物分别管理；模型不能把输入 URL 或错误返回中的任意地址包装成“生成成功”。

## 持久文件

可信执行回执中的资源被校验并保存，登记关联 owner、Session、Run、文件名、类型、大小和 SHA-256。最终回复依据登记的产物事实，不依据模型编造的链接或尺寸。

标准 MCP resource_link 与明确结果容器可以提供产物，媒体类型决定显示方式，不按服务名猜视频。重复资源去重；是否发布中间文件由工作流及明确发布清单决定，不在框架中写死“第一张隐藏”等业务规则。

文件下载与网页预览由 `EXOHARNESS_MEDIA_PUBLIC_BASE_URL` 生成地址。本地默认 `http://127.0.0.1:9790`，公网需配置实际 HTTPS 域名，不能将本机地址返回给远程浏览器或 MCP。

## 下载和播放

下载使用签名 URL，默认无到期时间。访问依赖文件保留和签名密钥有效。签名链接授予文件访问权，按敏感凭据管理，并从公开日志中脱敏。

图片按正确 MIME 解码；MP3/MP4 等支持 Range 和 206 响应以便浏览器拖动播放。元数据和文件内容的摘要/大小必须一致。文件端不依赖用户 Cookie，也不提供任意外部 URL 代理。

## 网页项目

单文件下载与预览分开，多文件项目预览由发布清单确定入口及资源。相对 CSS、JS、图片和二级页面保持可访问；不提供目录列举，不执行后端服务。

隔离预览使用受限 CSP / iframe sandbox，不授予主站同源权限。浏览器验收需检查脚本、资源、导航、移动布局和控制台错误，而不只是 index.html 能下载。

## 输入附件

上传文件保存到私有存储，普通任务向模型传递元信息或引用。MCP 使用符合授权和来源限制的可访问地址。图片识别与参考方式根据用户意图、Skill 和服务 Schema 确定。

实现：`modules/artifacts`、`modules/api/src/media/`、`modules/api/src/chat/attachments.rs`。当前 HTTP 文件路由见 [API](INTERFACES.md)，网络和凭据边界见 [安全](SECURITY.md)。
