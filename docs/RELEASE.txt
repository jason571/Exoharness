Contents: bin/exoharness, web/, scripts/, and build-manifest.json.
The manifest records SHA-256 digests. The package excludes source code,
databases, user data, and credentials.

Requirements for the Linux x86_64 GNU binary:
  Linux x86_64 with glibc 2.39 or newer (for example Ubuntu 24.04).
  Python 3.11 or newer, Docker Engine, and permission to use Docker.
  An available PostgreSQL server; the commands below provision one in Docker.
  Models, credentials, Skills, MCP services, and the OCI execution image are
  configured separately. They are not included in this download.

Native operation (from the extracted package directory):
  docker pull postgres:18.6-alpine3.23
  bash scripts/start-native.sh prepare-db
  bash scripts/start-native.sh start
  bash scripts/start-native.sh status
  bash scripts/start-native.sh restart
  bash scripts/start-native.sh stop

prepare-db uses a cached PostgreSQL image. For a first deployment, obtain
postgres:18.6-alpine3.23 before running the command. An existing PostgreSQL
server can be configured through environment variables instead.

Open http://127.0.0.1:9797/ for administration and
http://127.0.0.1:9798/ for the user portal after startup. Configure a model
connection and an assistant before running model-backed tasks. User signup
requires SMTP configuration; administrator access is bootstrapped locally.

Display local access credentials with:
  bash scripts/start-native.sh access
Do not share this command's output.

Set the administrator password with:
  bash scripts/start-native.sh set-admin-password

Show the private data directory with:
  bash scripts/start-native.sh data-path

Container operation (stop native mode first):
  bash scripts/start-docker.sh start
  bash scripts/start-docker.sh status
  bash scripts/start-docker.sh restart
  bash scripts/start-docker.sh stop

Use a cached compatible image. Startup checks ABI compatibility and does not
automatically build or pull an image. Container mode uses host networking and
does not expose the host Docker socket to the API container. Chat, management,
and remote MCP are supported; full OCI code execution currently requires the
native main-service mode. Python, Shell, JavaScript, and TypeScript tasks run
in a separate OCI execution image. See the source README and
runtime/sandbox/Dockerfile for building that image. Docker Engine access is
required for the OCI backend.

Default loopback listeners: management 9797, user portal 9798, and file service
9790. Configure EXOHARNESS_BIND, EXOHARNESS_PORTAL_BIND, and
EXOHARNESS_MEDIA_BIND to change them. Set EXOHARNESS_MEDIA_PUBLIC_BASE_URL for
public download and preview links. Configure an existing PostgreSQL server
with EXOHARNESS_DATABASE_URL and a separate password file.

Register capability packages, model connections, credentials, runtime
dependencies, and external services as required by the deployment.

Native service logs are written to service.log in the private data directory.
Frontend assets are embedded in the executable. Rebuild the release and
restart the service after changing pages. Recovery, self-installation, and
cross-MCP shared resource pool status is documented in docs/STATUS.md.

For public deployment, use a correctly configured HTTPS proxy and observe
Host/Origin and Cookie security boundaries. Do not expose local validation
ports directly to the Internet.

The source build does not require Docker. See docs/DEPLOYMENT.md for the full
build and deployment guide.
